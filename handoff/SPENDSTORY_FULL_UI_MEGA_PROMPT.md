## Shared app shell and interaction language

- Keep the light lavender frame, near-full desktop width, indigo and magenta chart colors, and compact sidebar. Apply the same spacing, typography, button variants, status badges and surface treatment across all five pages. Fix awkward label and action wrapping at 1280px. Prefer concise user copy and one clear page heading. Let the desktop toolbar stick within the scrolling content, and give mobile a compact layout with accessible navigation.
- Give each page the controls it needs. Keep search available where it makes sense and preserve the one-submit path to filtered Transactions. Clarify which view uses the selected month, which uses all records, and which uses a separate evaluation dataset. Put data management actions in a consistent, discoverable place. Preserve shareable `nav` and `month` links and the current single-click navigation behavior through Streamlit reruns. Test when the review badge count changes.
- Give every actionable element appropriate hover, keyboard focus, active, pending and disabled states. Use visible text or labels for actions with icons. Support pointer, keyboard and touch. Keep focus stable through a save and return focus when closing an overlay. Use Escape to dismiss dialogs where supported. Prevent accidental double submissions. Keep clear empty, loading, success and error states. Put errors near the fields they concern and preserve entered values on validation failures.
- Motion should explain what changed. Use roughly 120–180ms for hover, focus and tooltip transitions, 180–260ms for a panel entrance or state change, and 300–500ms for initial chart reveals. Animate opacity and small transforms when practical. Keep layout stable and avoid replaying chart and page entrances on every Streamlit rerun, pointer movement, or unrelated edit. Preserve the chart's current selection when appropriate. Honor `prefers-reduced-motion`, including the reflection effect and smooth scroll. Audit motion in a real browser with both preferences.
- Use native widgets when they fit the interaction. Extend the existing isolated Streamlit component for custom charts rather than bringing in a second UI stack. Keep persisted state in Python. Treat client chart events as untrusted selections and validate month, category, and transaction IDs against current records. Keep the interface usable offline.

## Budgets

Make “No target” distinct from an intentional zero target. Preserve untouched targets and prevent draft values carrying into a different month.

3. Test no target, zero, under, exactly at, and over target. Confirm that saving in one month only changes that month and refreshes Overview. Make the view comfortable with a narrow mobile viewport and keyboard-only input.
